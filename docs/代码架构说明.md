# 金融新闻分析系统 — 代码架构说明

本文档对应实施计划见：[金融新闻分析系统_d1f1a06f.plan.md](./金融新闻分析系统_d1f1a06f.plan.md)。目的在于说明各 `.py` 文件的职责与复用方式，便于二次开发或迁移模块。

---

## 1. 总体架构与数据流

系统分为三层：

1. **配置与基础设施**：环境变量、数据库连接、ORM 模型。
2. **业务管道**：采集（Tushare）→ AI 筛选 → AI 详细分析，经 `content_hash` 关联三张表。
3. **对外能力**：Flask JSON API、静态站点数据导出（`web_display`）、各类运维/批处理脚本。

典型主链路（与计划书一致）：

```text
run_task.py / run_pipeline_*.py
  → news_fetcher.fetch_latest_news  → raw_news
  → news_filter.filter_news         → selected_news（relevance=True）
  → news_analyzer.analyze_news      → news_analysis_detail
```

Web：`app.py` 从 `news_analysis_detail` 读数据；`sync_news_to_display.py` 可把同表数据导出为 `web_display/data/feed.json` 供纯静态页使用。

## 2. 根目录：核心库与入口

| 文件 | 用途 | 复用要点 |
|------|------|----------|
| **config.py** | 从环境变量及默认 `.env` 路径加载配置；提供 `DatabaseConfig`、`TushareConfig`、`DoubaoConfig` 与全局 `settings`。 | 新脚本只需 `from config import settings` 即可读库与 API 配置；ECS 上注意 `DB_HOST` 用内网地址。 |
| **models.py** | SQLAlchemy 声明式模型：`RawNews`、`SelectedNews`、`NewsAnalysisDetail`；创建 `engine`、`SessionLocal`、`get_db_session()`；连接后设置 MySQL 会话时区为 `+08:00`。 | 所有需要访问数据库的代码应通过 `get_db_session()` 与这些模型交互，避免重复建连接逻辑。 |
| **utils.py** | `compute_content_hash`（标题+正文 MD5）、`now_beijing_naive()`、`parse_news_datetime()`。 | 去重与时间口径与采集/入库一致，复用时不要另写一套 hash 规则。 |
| **news_sources.py** | Tushare 来源配置（华尔街见闻、新浪等）、`get_sources_by_ids`；预留 `NormalizedNewsRecord` / `BaseNewsFetcher` 协议便于扩展非 Tushare 源。 | 增新闻源时优先改 `TUSHARE_SOURCES` 或实现协议后在 `news_fetcher` 中接入。 |
| **news_fetcher.py** | 调用 Tushare `pro.news()` 多源拉取、同源/跨源与库内 `content_hash` 去重、写入 `raw_news`；支持命令行参数（时间窗、来源等）。 | 对外主函数：`fetch_latest_news(...)`，返回 `(新增 RawNews 列表, content_hash 列表)`，供流水线只处理本批 hash。 |
| **prompts.py** | 豆包筛选/详细分析用的提示词模板 `FILTER_PROMPT_TEMPLATE`、`ANALYZE_PROMPT_TEMPLATE`（含 `{title}`、`{content}`）。 | 调优分析质量主要改此文件；需与 `news_analysis_detail` 字段语义保持一致。 |
| **doubao_client.py** | 火山引擎 Ark `Responses API` 封装：`chat`、`chat_with_usage`、`parse_json_from_text` 等；含重试与 token 用量解析。 | `news_filter` / `news_analyzer` 均依赖此模块；其他 LLM 任务可复用 `chat_with_usage`。 |
| **news_filter.py** | 对未进入 `selected_news` 的 `raw_news` 调用筛选提示词，解析 `relevance`/`direction`/`impact`；支持 `only_content_hashes` 限制本批、可选 `token_accumulator`。 | 复用 API：`call_doubao_filter_api`；批处理：`filter_news(...)`。 |
| **news_analyzer.py** | 对已在 `selected_news` 但未写入 `news_analysis_detail` 的记录做详细分析，解析多字段 JSON 并入库；含字段规范化函数（如 `_norm_list`）。 | 复用 API：`call_doubao_analyze_api`；批处理：`analyze_news(...)`。 |
| **run_task.py** | **定时任务精简入口**：顺序执行采集 → 筛选 → 分析，各步骤独立 try/except，无报告文件、适合高频 cron。 | 云上“每 N 秒跑一轮”可直接指向此脚本。 |
| **run_pipeline_90s.py** | **90 秒采集窗口**流水线：仅日志、不写报告；筛选/分析仅处理本批 `content_hash`。 | 与阿里云 90 秒触发配套，见同目录 `run_pipeline_90s_loop.sh`。 |
| **run_pipeline_manual.py** | **可配置窗口**（默认 60 分钟，可用环境变量 `FETCH_WINDOW_MINUTES` 覆盖）：写 `pipeline_report.txt` 并尝试在本机打开。 | 本地或运维手动跑一轮、看耗时与 Token 统计时使用。 |
| **run_pipeline_once.py** | 设计意图与 `run_pipeline_manual` 类似（采集约 10 分钟窗、写报告）；**当前仓库中该文件存在重复/损坏片段，执行前请核对源码完整性**，优先使用 `run_pipeline_manual.py`。 | — |
| **run_analysis_latest_20.py** | 针对库中最新若干条 `raw_news` 逐条跑筛选+详细分析并写库，另导出可读文本报告（如 `analysis_report.txt`）。 | 适合服务器上“补分析”或抽查最新数据，而非全量定时任务。 |
| **app.py** | Flask 应用：`create_app()` 注册 `/`、`/api/news`、`/api/news/<id>`、`/api/stats`。 | 部署时用 `gunicorn app:app` 等形式；前端模板在 `templates/`，静态资源在 `static/`。 |
| **init_db.py** | 执行 `Base.metadata.create_all`；对旧库补列（`content_hash`、`relevance`、`news_analysis_detail` 扩展列、`MEDIUMTEXT` 等）。 | 新环境或迁移后先跑一次。 |
| **sync_news_to_display.py** | 将 `news_analysis_detail` 导出为 `web_display/data/feed.json`（可选 `--no-change` 仅在数据变化时写入）；带简单状态文件减少无效 IO。 | 静态展示站点 + cron 同步时使用，与 Flask 可并行存在。 |
| **check_db.py** | 使用 `pymysql` 直连测试 `settings.db` 是否可连通（打印 `DB_OK` / `DB_FAIL`）。 | 部署排障、验证环境变量。 |
| **fix_crlf.py** | 一次性工具：将指定文件换行转为 LF。 | 修复脚本在 Linux 上执行异常时的行尾问题。 |

## 3. 根目录：调试与临时测试脚本

以下脚本**非生产流水线依赖**，用于联调或一次性验证：

| 文件 | 用途 |
|------|------|
| **debug_doubao.py** | 打印豆包 API 响应中 `output` 结构，便于适配解析逻辑。 |
| **debug_filter_response.py** | 对样例标题/正文跑筛选提示词，打印原始文本与 `parse_json_from_text` 结果。 |
| **debug_news_api.py** | 直接调 Tushare `pro.news`，打印时间窗与返回列名、样例行。 |
| **test_api.py** | 串联测试 Tushare 与豆包是否配置正确、能否返回数据。 |
| **test_filter_once.py** | 小批量（如 `limit=2`）调用 `filter_news` 验证筛选链路。 |
| **test_tushare_news.py** | 多时间窗测试 `pro.news`，确认接口与账号权限。 |

## 4. `scripts/` 目录：批处理与评估

均在项目根下执行时需保证 `sys.path` 含项目根（脚本内已多处 `insert`）。

| 文件 | 用途 |
|------|------|
| **export_recent_news_csv.py** | 导出最近 N 分钟内 `raw_news` / `selected_news` 为 CSV（默认 `news/`）。 |
| **export_latest_selected_20.py** | 导出最新 20 条 `selected_news` 到 `news/selected_news_latest_20.csv`。 |
| **run_recent_pipeline_and_export.py** | 拉取近 30 分钟新闻 → 按本批 hash 筛选 → 调用 `export_recent_news_csv` 导出。 |
| **run_filter_and_export_quick.py** | 快速 `filter_news(limit=8)` + 导出最近 30 分钟 CSV。 |
| **analyze_selected_csv_to_md.py** | 读取筛选结果 CSV，对每条调用 `call_doubao_analyze_api`，生成 Markdown（不落库或按脚本逻辑而定，便于人工阅读）。 |
| **compare_prompts_on_selected_csv.py** | 在同一批 CSV 上对比「旧/新」详细分析提示词（需在脚本内编辑 `NEW_PROMPT_TEMPLATE`），用于提示词 A/B。 |
| **check_raw_relevance.py** | 直连 MySQL 检查 `raw_news.relevance` 列是否存在（Schema 排查）。 |

## 6. 复用建议（按场景）

- **只想要采集+去重入库**：`config` + `models` + `utils` + `news_sources` + `news_fetcher`。
- **接入自己的 LLM**：保留 `prompts` 与 `news_filter`/`news_analyzer` 的解析形状，替换或封装 `doubao_client` 中的 HTTP 调用。
- **只做展示、不跑 AI**：`models` + `app.py` 或 `sync_news_to_display.py` + `web_display`。
- **定时全链路**：Linux/ECS 用 `run_pipeline_90s.py` 或 `run_task.py`；需要人工可读报告用 `run_pipeline_manual.py`。
